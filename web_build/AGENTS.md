# web_build: notes for agents

What is not obvious from the code of this library. The rules that hold for every library, the commands and the map of the libraries are in [../AGENTS.md](../AGENTS.md); the user facing description is in README.md.

- `wasm_build.odin` (`WasmBuild`: freestanding_wasm32 (or js without an entry) for a module that a host loads, not a page; `require_exports`, `require_memory`, `allowed_import_modules`) and `wasm_inspect.odin` (`WasmInspect`: the imports and exports of a binary, builds for every target; used by spacetimedb's `BuildModule`).
- `resource.odin` (`ResourceLoad` with `RESOURCE_PATH` / `RESOURCE_EMBED` configs, builds for js so no os/testing there; tests in `resource_test.odin`, disk read in `resource_file.odin`), `web_build.odin` (`WebBuild`, js_wasm32 build of a package with init/step/shutdown, tests at the bottom run a real build), `templates/`. Demos: `demo_raylib/` (desktop), `demo_karl2d/` (`game/` is the web package, `build_web/` calls `WebBuild`).
- Test `test_a_program_that_uses_simd_or_font_links_without_the_simd128_flag` builds programs that import `simd` and `font` for js_wasm32 WITHOUT `-target-features:simd128` (it calls `odin build` itself, `WebBuild` passes the flag), through `-collection:odin_utilities=<root>` (an absolute path is not an import path). It guards `simd/text_vector.odin`: remove the `textFillPortable` early return and it fails with the LLVM message.
- `web_check.odin` (`#+build !js`): `WebBuildCheck(config)` serves `<source>/bin/web` with web_serve in a thread and loads it in a headless Chrome or Edge (`WebBuildBrowserFind`), reading the console from the browser log (`--enable-logging=stderr`: every console message is a `:CONSOLE:` line whatever its level, so an error is told by its text, `webBuildConsoleError`). Status PASSED, FAILED (message lists the errors), NO_BROWSER (never a failure), NOT_RUN. It catches a page that links and does not start (the wrong import name of file_browser.js). The build tools of the demos take `--check`; the test builds a good and a broken page. Needs a browser, so tests skip without one.
- The page template has an inline icon (`<link rel="icon" href="data:,">`): without it Chrome asks for /favicon.ico and logs a console 404, which `browser_drive` (and `WebBuildCheck`) report as an error.
