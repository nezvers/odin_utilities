# demo_kit: notes for agents

What is not obvious from the code of this library. The rules that hold for every library, the commands and the map of the libraries are in [../AGENTS.md](../AGENTS.md); the user facing description is in README.md.

- `Backend` (table of procs: shapes, text, textures, sound, camera, clip, mouse capture) implemented by `demo_kit/glue_raylib`, `demo_kit/glue_karl2d` and `HeadlessInit` (no window, drawing is counted). `Input` is plain data per frame, `Context` is what a demo proc gets. `gui.odin` has Button/Toggle/Slider/Spinner.
- The raylib backend of the kit draws text from glyphs made at the drawn size with the exact advances of the font file (`sizedFace`, `drawText`, `measureText` in `demo_kit/glue_raylib`), as Karl2D's dynamic fonts do: do not go back to `DrawTextEx` on a scaled atlas (blurred, crowded letters, pictures that differ from Karl2D). `FontLoad` bytes must outlive the font. `ui/glue_raylib` does the same for `Fonts` (`sizedFace`, `drawText`, `measureText`; the cache is in the `Fonts` struct).
- Runtime tests: a demo's `script` is a `[]kit.Step` (Wait, Tap, Hold, Click, Drag, MoveTo, Scroll, LookBy, Type, Check(proc, message)); a Player turns it into input. Constructors are contextless so a script can be a global. `odin test <lib>/demo_common` runs it headless, `odin run <lib>/demo_raylib -define:DEMO_TEST=true` plays it in the window (exit code 1 on a failed check). A demo without script is a 60 frame smoke test.
- Screen capture tests: script step `kit.Capture("name")` compares the drawn frame with `captures/<backend>/<name>.png` next to the script file; only in a window with `-define:DEMO_CAPTURE=true` (new goldens are written when missing, `-define:DEMO_CAPTURE_UPDATE=true` replaces them). Headless skips it. `odin run demo_kit/tool/captures` (from odin_utilities; `-- ui reports`, `-- --karl2d`, `-- --update ui`, `-- --allow-new`, `-- --monitor <name>`) runs them for every library that has Capture steps and exits 1 on a changed picture, 2 on a new one: run it before committing a change to drawing, text layout or a style, and look at every `.actual.png` it leaves. The windows go to the display named by `--monitor`, `DEMO_MONITOR` or the local file `demo_kit/monitor.txt` (git ignored), with a size that does not depend on the scaling of the display (Karl2D `disable_auto_scale_hint`, raylib resized after it moved): the goldens are 1280 x 720 on every display. See demo_kit/README.md.
- The log of a scripted run (`demo_kit/log.odin`): `DEMO_LOG=stdout|stderr|<file>` and `DEMO_LOG_KINDS=input,reaction,frame` in the environment dump the steps, the input they produce, the checks and captures with their timing; `kit.LogNote(ctx, ...)` adds a line from a demo; the time in a line is simulated (two runs diff equal).
- Strings with apostrophes break multi file bash heredocs here: write demo files with the Write tool.
