# p2p: notes for agents

What is not obvious from the code of this library. The rules that hold for every library, the commands and the map of the libraries are in [../AGENTS.md](../AGENTS.md); the user facing description is in README.md.

- Serverless connection by pasted codes: `stun.odin` (RFC 5389 + CHANGE-REQUEST, pure), `code.odin` (`Invite`: candidates incl. one IPv6, NAT facts; text = Crockford base32 + crc32 over a `serial` Writer), `link.odin` (`Link`: IPv4+IPv6 sockets or a `Transport`, STUN gathering, NAT mapping/filtering measurement, hole punching, port guessing for symmetric NATs, selective repeat reliable channel, events, inbox; fixed capacities, ~320 KB, heap or global; `now_ms` is a parameter), `portmap.odin` (PCP, NAT-PMP, UPnP IGD, blocking and time bounded), `turn.odin` (TURN client, long term credentials, non blocking from `LinkUpdate`), `derp.odin` + `derp_link.odin` (free Tailscale DERP relays, failure kinds + advice, automatic reconnect with backoff, custom relay by name in invites, `tool/derp diagnose|map`: client, pseudo-address candidate, SIGNAL packets so the guest reply needs no pasting, direct-path upgrade), `tls13.odin` (minimal TLS 1.3 client, verified against RFC 8448) + `tls_verify.odin` (server certificate: chain, name, dates, CertificateVerify through core:crypto/x509; roots = two built in from `trust/`, the system store (Windows CryptoAPI / PEM bundles), `P2P_CA_FILE`; on Windows a root the store lacks is looked up through CryptoAPI; `P2P_TLS_VERIFY=off`) + `tls_revoke.odin` (CRL revocation of the chain, `P2P_TLS_REVOCATION=soft|strict|off`), `nacl.odin` (box, verified against the derpnet C code; `references/derpnet` is the reference checkout), `sim_derp_test.odin` (fake relay in the NAT simulation), `relay_find.odin` (`RelayFind`: which TURN servers answer from here, unauthenticated Allocate, list of candidates with free-tier sign-up links), `wireguard/` (separate package: optional encrypted tunnel, keys with core:crypto x25519, installs WireGuard on request, official signed installer on Windows / package manager on Linux, every step logged before it runs, needs administrator rights; Windows and Linux only), `sim_test.odin` (simulated internet: NATs of every mapping/filtering kind, LANs, IPv6 firewalls, STUN with a second address, TURN server; the NAT pair matrix and relay/IPv6 scenarios run there), `tool/chat|probe|portmap|turn|multi` (terminal programs; `multi [n] [chat flags]` starts a host and n-1 guests as processes, passes the codes, merges the output with timestamps and checks everybody heard everybody, up to 8, exit code 0/1; chat has `--find-relay`, `--wireguard [--yes]`, `--wireguard-dry` (whole key exchange and switch without touching the system, used for tests), `odin run p2p/tool/<name>`). No demo_kit demo: it needs a real network and two programs. `proxy.odin` + `proxy_ntlm.odin` + `proxy_sspi_*.odin` + `proxy_tunnel.odin` (http, https, socks5, socks4 proxies through HTTPS_PROXY / ALL_PROXY for the relay; Basic, NTLM, Windows SSPI Negotiate logins), `channel_probe.odin` (is another member the host of a relay channel too). Every packet is sealed with a key from the secret in the invite (`Invite.secret`, `PeerSeal`/`PeerOpen` in link.odin, replay window); a relay of the list that stays down is replaced along `DERP_FALLBACK`. Not for js (core:net); limits and measured free servers in its README.
- `odin test p2p -strict-style -vet` (64 tests, ~3 s, `P2P_LIVE=1` adds a live relay test) and `odin test p2p/wireguard -strict-style -vet` (4 tests), `odin check p2p/tool/<name> -strict-style -vet`. The `Link` and `PortMapState` are too big for a stack: `new(...)` in tests. Tests that use real sockets sleep a millisecond per pump (loopback delivery is not instant); the simulation needs no sleep.
- Findings worth knowing: a real STUN server drops a request whose datagram is longer than its header says (send `request[:length]`); a pipe handed to a child process on Windows keeps the child waiting for end of input (give `clip` a temp file as stdin); the CHANGE-REQUEST result includes the PC firewall.
