# gdextension: notes for agents

What is not obvious from the code of this library. The rules that hold for every library, the commands and the map of the libraries are in [../AGENTS.md](../AGENTS.md); the user facing description is in README.md.

## Files
- `interface.odin`: the used part of `gdextension_interface.h` (structs as the header lays them out, the functions looked up once from `get_proc_address` into `gd`, Variant and PackedByteArray helpers). Godot 4.7.2 was the reference; the class is registered with `classdb_register_extension_class4` (kept since 4.4).
- `class.odin`: the public API: `Class`, `Method`, `Value`, `Entry`. `registerClass` builds the property infos and method infos (heap, once), `callMethod` and `ptrCallMethod` are the two ways Godot calls a method.
- `tool/build`: the build tool (package main with tests): it calls `odin build -build-mode:dll` and writes the `.gdextension`; the entry symbol is the first line with `:: proc "c"` and `GetProcAddress` in the package's `.odin` files. Godot copies the loaded DLL as `~name.dll` into `bin/` (git ignore `bin/`).
- `engine/engine.odin` is GENERATED by `tool/bindings` from `godot_api/extension_api.json` (version 4.7.2 here): never edit it. Regenerate with `odin run gdextension/tool/bindings -- --classes Object,Node,Node2D,Node3D,CanvasItem,Control,Label,Timer --out gdextension/engine/engine.odin` (the class list is the same one; keep it in sync with this line). Inherited methods are only in the wrapper of the declaring class. In the generator `fmt` needs `{{` for a literal `{` in a format string with arguments.
- `template/`: the template and testing ground (see its AGENTS.md): every new feature of the library appears there first.
- `godot_spacetimedb/`: the example and first user (own AGENTS.md). `godot_api/`: dumps of the interface of Godot (git ignored).

## Gotchas learned
- Every `GDExtensionPropertyInfo` needs real `name`, `class_name` and `hint_string` (a valid empty String/StringName): a nil `hint_string` crashes Godot at load (signal 11 inside registration).
- Sizes: String and StringName are 8 bytes, a PackedByteArray 16, a Variant 24. A String made for Godot must be destroyed after the Variant copy is made (`variantString`).
- A builtin method called through `variant_get_ptr_builtin_method` needs a real result pointer even when ignored (`resize` writes an error code: nil crashes). The hashes of `size` and `resize` are from `extension_api.json`.
- Every `proc "c"` callback sets `context = runtime.default_context()` first; temp memory is freed at the end of each call.
- A DLL that Godot loads is copied as `~name.dll` next to it: git ignore `bin/`.
- A test folder must not be called `test`: `odin run tool/test` writes `test.exe` and the package exe would clash.
- Signals: registered with `classdb_register_extension_class_signal` (argument infos as for methods); `Emit` calls `Object.emit_signal` (vararg, hash 4047867050 from extension_api.json) through `object_method_bind_call` with the signal name as a StringName Variant first. All Variants it builds are destroyed with `variant_destroy`. A signal must not share a name with a method of the class (GDScript then sees the method: `connect` not found on Callable).
- Virtuals use `get_virtual_call_data_func` + `call_virtual_with_data_func` (the plain `get_virtual_func` callback has no userdata, so it cannot tell which proc to call): the data is the `Virtual` row, found by comparing the interned StringName pointers. The engine asks for every virtual of the parent; nil means not overridden. One table of methods can serve two classes (RefCounted and Node), but not by copying one global into another (not constant): use named procs and arrays.
- `Call` goes through the Variant path of `object_method_bind_call` (the same one as `Emit`): default arguments of the engine method are filled in by the engine (`get_child_count` takes none from us), method binds are cached by the ADDRESSES of the class and method strings (pass literals), 64 entries. An OBJECT Variant of a RefCounted holds a reference while the Variant lives: `Call` destroys its Variants.
- Each packed array type has its own `size` and `resize` (`PackedOps` in interface.odin, loaded by `packedLoad` from the names `packed_<type>_array_operator_index[_const]`): the functions of PackedByteArray cannot be used on the others. Numbers are copied with one `copy` from the pointer of element 0.
- Array and Dictionary: read and written element by element through `array_operator_index*`, `dictionary_operator_index*` and the builtin methods `size`, `resize`, `keys` (hashes from extension_api.json). Strings are measured first (`string_to_utf8` with a nil buffer gives the length) so a big array does not allocate the 128 KB text buffer per element. An Array that arrives as a Variant is copied out with `to_array` and must be destroyed; a ptrcall argument is the engine's own and is not.
- Properties are registered after the methods; the engine looks the getter and setter up by name when they are used, so a name that is not a registered method fails only then. The setter StringName of a read only property is empty.
- Vectors are 32 bit floats in the engine (the usual build; a double precision build would break the native ptrcall layout). Adding an argument kind: a `ValueKind`, a `variantTypeOf` row, a row in both adapters and the helpers in interface.odin.
- The numeric packed arrays (Int32, Float32, Vector2, Vector3, Color) share one reader and one writer (`readPackedNumeric`, `writePackedNumeric`, `packedOpsOf`): their elements lie one after the other, so a vector array is a `[]f32` of `count * components` numbers (`floats32`). `size` and `resize` have the same hashes for every packed type. A trailing part of `floats32` that does not fill an element is dropped when written.
- Nesting: `variantToValue(variant, allocator, depth)` reads Arrays, Dictionaries and packed arrays inside each other (`MAX_NESTING` 8, deeper is NONE: an Array that holds itself cannot run away). `valueToVariant` writes them back, so a `Value` tree round trips. `VARIANT` is the type NIL with `PROPERTY_USAGE_NIL_IS_VARIANT` (`usageOf`): the Value comes with the kind that really arrived (do not overwrite `kind` after reading it), a ptrcall Variant result is zeroed first (all zero is nil) and a Value that has no kind stays nil.
- Plain structs (`podInfoOf` table: variant type, number count, 32 bit int or float, `real` or `floats32`): the native memory is the numbers one after the other, so `podRead`/`podWrite` serve the ptrcall path and `podToVariant`/`variantToPod` (a 64 byte buffer, the Projection is the biggest) the Variant path; the layouts are in the comment of `PodInfo`. StringName and NodePath go through the String constructors (`string_from_name`, `name_from_string`, indexes 2 and 3 of `String` and 2 of the others). Inside an Array a StringName still arrives as a `STRING` (kept for old code), the other structs keep their own kind. RID, Callable, Signal come as NONE.
- `tool/bindings` types: Vector2i..Plane are `[N]f64` (`[N]i64` for the integer ones), AABB, Transform2D, Basis, Transform3D, Projection and the packed number arrays are `[]f32`/`[]i32`/`[]i64`/`[]f64`/`[]u8` (results live in temp memory), Array and PackedStringArray are `[]ge.Value`, Dictionary and Variant are a `ge.Value` (a Variant argument is a Value of the kind to send, `{}` is nil). A typed Array (`typedarray::Node`) is only taken as a result: the engine checks the element type of an argument and an Array made here has none. Callable, Signal, RID still leave a method out.
- Hot reload (`reloadable = true` under `[configuration]`): the engine saves the properties with the STORAGE flag of every object of the extension, unloads the library, loads the new one (a copy, so the original can be rebuilt), calls `recreate_instance_func` (`recreateInstance`: a new instance for the old object, `bind` again) for each object and sets the saved properties back through the setters. So what is not a property is lost on a reload, and a class without `recreate_instance_func` disables reloading for the whole extension (the engine says so in the log). Reload only runs in the editor (`Engine.is_extension_reloading_enabled`, set by `--editor`; the editor reloads by itself when its window gets focus and the file changed): a test cannot do it from `--script`, it uses an editor plugin (`template/godot_project/addons/reload_test`) that starts only when it gets two arguments after `--`. A reload that fails leaves the editor waiting, so the test command has `--quit-after`.
- Property hints: `Class.hints` (`Hint{property, hint, text}`) are matched by property NAME at registration; the text becomes a real String kept in `class.property_hints` (the engine reads `hint_string` later, so it must live as long as the class). Kept apart from `Property` because Odin positional literals need every field, which would break every `{name, kind, getter, setter}`. Groups (`Class.groups`, `classdb_register_extension_class_property_group/subgroup`) apply to the properties registered after them, so the group is emitted just before the property named in `before`; the group names are kept in `class.group_texts`. Static methods (`Class.statics`, flag 32 in `method_flags`): the engine passes a nil instance, so a static method must not touch it. Constants (`Class.constants`, `classdb_register_extension_class_integer_constant`) are registered after the methods and properties; the names are temporary StringNames (the engine copies them). Enum values: `Off,Low:5` (an INT property gets the numbers after the colon).
