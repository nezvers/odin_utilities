# spacetimedb: notes for agents

What is not obvious from the code of this library. The rules that hold for every library, the commands and the map of the libraries are in [../AGENTS.md](../AGENTS.md); the user facing description is in README.md. Next steps: `TODO.md`.

## Setup and server
- `setup.odin` `SetupRun(options)`: clones SpacetimeDB into `spacetimedb/SpacetimeDB` (vendored, untracked via `spacetimedb/.gitignore`), the other references into `odin_utilities/references/` (own `.gitignore *`), downloads the server release (`SPACETIMEDB_VERSION`) into `spacetimedb/bin`, builds `fixtures/basic-rs` with cargo (skipped without cargo). Other libraries call it from their setup. Run: `odin run spacetimedb/tool/setup`.
- `server.odin` `ServerStart/ServerStop`: start through the CLI with `--root-dir` (it makes the jwt keys and starts the standalone server as a child), so stop kills the whole tree. Output is discarded unless `show_output` or `log_file` (Windows: a generated `start_server.cmd` does the redirection, its path needs backslashes); `lan` listens on 0.0.0.0. Output is discarded unless `show_output` (an `os.create` handle is not inherited by children on Windows; an inherited test pipe hangs the runner).

## Client
- `http.odin` `HttpRequest` into a caller buffer; `rest.odin`: identity, publish, delete, schema, SQL, call, logs.
- `bsatn/` is its own package (no sockets, builds for wasm); `bsatn_alias.odin` re-exports it. `Writer/Reader` work over caller memory and remember the first error.
- `protocol.odin`: websocket protocol v2 (`Encode...` for client messages, `ServerMessageDecode` with an allocator for arrays; strings and bytes point into the frame).
- `cache.odin`: client cache over caller storage (`CacheInit`, `CacheTableAdd(name, key_size)`, `CacheApply(message)`, `CacheEvents`, `CacheFind`, `CacheNext`, `CacheCollect`). Rows keep an 8 byte header in `bytes` (compacted when full); a row points into the cache until the next apply; events point into the frame. Tests: `cache_test.odin` and the session test.
- `codegen.odin` (`GenerateSource(schema_json, options)`, `#+build !js`) + `tool/generate`: Odin source from the schema JSON; `wide.odin` has the 128/256 bit readers it uses. `fixtures/generated/{basic,rich}` are the committed outputs of `fixtures/*.schema.json`; `codegen_test.odin` regenerates and compares them, compiles and tests them (`rich_test.odin` is by hand). After changing the generator regenerate them: `odin run spacetimedb/tool/generate -- --schema spacetimedb/fixtures/rich.schema.json --package rich --library ../../.. --out spacetimedb/fixtures/generated/rich/rich.odin`.
- `stream.odin`: TCP + optional TLS 1.3 (`Endpoint.secure`, p2p `TlsConnect`); http and websocket only use `streamOpen/streamSend/streamRecv`. `Stream` holds a ~55 KB `p2p.Tls`, so a `WebSocket`/`Connection` is big (heap or global). `SPACETIMEDB_LIVE=1 odin test spacetimedb` also pings maincloud over TLS.
- `tunnel/`: TCP over a p2p Link (host dials the server, guest listens on a local port); `StreamIdle` lets a blocking HTTP call step the tunnel. `arena/`: the sample game (own AGENTS.md).
- `websocket.odin`: RFC 6455 client, non blocking, `WebSocketPoll`. `connection.odin`: `ConnectionOpen/Poll/Subscribe/SubscribeBatch/CallReducer/CallProcedure/Reconnect/Maintain`, asks for `compression=None`; the connection remembers its subscriptions (query strings by reference) and the token for a reconnect.

## Modules in Odin
- `module/` (package `spacetimedb_module`): module for `freestanding_wasm32`, fixed buffers, `Define(define)` called from an `__preinit__...` export, `TableAdd/ReducerAdd`, exports `__describe_module__` and `__call_reducer__`. Examples `module/example/basic` and `module/example/rich` (keys, indexes, option/array/identity columns, schedule; `module_rich_test.odin`). ABI functions of later versions are separate `foreign import` blocks (`spacetime_10.4` point scans, `10.5` clear): a module imports only what it calls, and `datastore_clear` in 10.0 does not exist (the server says `unknown import`). A scheduled reducer takes one argument, a Ref to the table row type. Careful: `return count, call(&count)` reads count before the call.
- Build with `tool/build_module` / `BuildModule` = `web_build.WasmBuild` + `WasmInspect` (checks exports, memory, import namespaces).

## Tests and tools
- `spacetimedb_test.odin`: the session test is skipped when the server or module is missing. `tool/session` runs a session by hand. `fixtures/basic-rs`: Rust module (table `person`, reducer `add`).

## Where the truth is (shallow clones)
- `SpacetimeDB/crates/client-api-messages/src/websocket/v2.rs` the protocol; `crates/bindings-sys` the module ABI; `crates/bindings-cpp` a non Rust module model; `docs/docs/00300-resources` HTTP, BSATN, ABI docs.
- `references/`: BitCraftPublic, spacetimedb-python-sdk, spacetimedb-bindings-cpp, spacetimedb-cookbook, spacetime-studio.
- Not there yet: TLS socket, reconnect.
- `auth.odin` + `oidc/` (own library): signing in with OIDC. `AuthSession`/`AuthToken` give the ID token to `ConnectionConfig.token`, `ConnectionConfig.refresh` (`AuthRefresh`) renews it at every reconnect. The module side is `module/jwt.odin` (`module.Claims` via the host function `get_jwt` of `spacetime_10.2`, `module.RequireClaims` for issuer and audience; SpacetimeDB itself accepts any provider and does not check `aud`) with the example `module/example/auth`. `auth_test.odin` runs it all against a real server and the mock provider; the server fetches the discovery document of an `http://127.0.0.1` issuer. An HTTP request with the owner's token also runs `identity_connected`: a policy that refuses the owner's anonymous token refuses the owner's SQL too (query with the player's token).
- `tool/auth_live`: `odin run spacetimedb/tool/auth_live -- google|discord|spacetimeauth` runs the real thing: a throw away server (port 3191), the `auth` module, a real login with the ids of `oidc/providers/providers.local.txt`, the policy for that issuer and client id, an anonymous refusal and the person let in. Verified with Google: the server fetched Google's discovery document and keys itself and accepted the RS256 ID token (an owner row from the anonymous token is recorded before the policy is set).
- `auth_live` verified live with Google (earlier) and SpacetimeAuth (anonymous login method): the server accepted both RS256 ID tokens, `module.RequireClaims` let the person in on issuer and client id. SpacetimeAuth: public client, ID tokens last 15 minutes (`offline_access` for refresh), the subject of an anonymous user stays the same across logins.
