# reports: notes for agents

What is not obvious from the code of this library. The rules that hold for every library, the commands and the map of the libraries are in [../AGENTS.md](../AGENTS.md); the user facing description is in README.md.

- Reports of anything measured, checked or found: `reports.odin` (`Report` of sections of blocks: paragraph, table, facts, checks, findings, chart, code; `Column` with kind TEXT / NUMBER / RATIO, direction `better`, optional budget `limits`; the `Report...` builder procs add to the current section / block; one allocator for the whole report, an arena), `analysis.odin` (`RatioVerdict`, `TableColumnStats`), `render.odin` (`ReportRender` with `RenderOptions` into MARKDOWN, TEXT, XML, JSON, DIGEST; `CellProc` draws a cell the program's way), `digest.odin` (what stands out, for agents), `json.odin` (the canonical columnar file, version 1: `ReportWriteJson`, `ReportFromJson`), `import.odin` (`ReportImportMarkdown`: headings, tables, task lists as checks, `- **high**` findings, facts, code; `ReportParseResults` + `ReportBenchmarkTable` for `RESULT<TAB>case<TAB>value` lines), `compare.odin` (`ReportCompare`), `reports_test.odin` (16 tests). No file access in the library.
- `tool/reports` (render, digest, import, results, diff; exit code 3 with `--check`), `view/` (package `reports_view`: `ViewDraw` draws a report with the ui library: `UiSplit`, sortable tables, ratio bars, status colours, charts, a row filter), `demo_common/` (`viewer` on `bench_results.report.json`, `compare`, `status`; `screen.odin` is the ui storage sized for tables), `demo_raylib/`, `demo_karl2d/`. Details and limits in its README.
- `odin test reports -strict-style -vet` (16 tests, ~2 ms), `odin test reports/demo_common -strict-style -vet` (the scripts, headless). `odin test <pkg>` leaves `<pkg>.exe`: delete it. A string with a backslash or apostrophe in a Python patch script or a bash heredoc gets mangled: write files with the Write tool.
