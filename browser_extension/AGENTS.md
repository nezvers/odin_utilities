# browser_extension: notes for agents

What is not obvious from the code of this library. The rules that hold for every library, the commands and the map of the libraries are in [../AGENTS.md](../AGENTS.md); the user facing description is in README.md.

- Browser extensions written in Odin (wasm, `js_wasm32`) for Chrome/Opera/Edge (`chromium` build, MV3 service worker) and Firefox (MV3 event page). `browser_extension.odin` (`ExtensionConfig`, `ExtensionManifest`, `ExtensionBuild`: generated entry, main.wasm, unpacked folders, zip/xpi packages; build side, `#+build !js`, tests at the bottom), `install.odin` (`ExtensionInstall`: Chromium `--load-extension` in a profile of its own), `firefox_remote.odin` (installTemporaryAddon over the remote debugging protocol), `runtime/runtime.odin` (Odin side: `Log`, `SetBadge`, `ReplyPrint`), `templates/` (background.js, extension.js, popup, content script, entry template), `demo/` (example extension + `demo/tool`, run from the library folder: `odin run demo/tool -- all [--install]`), `.vscode/` (build and install tasks and launch configs).
- The source package contract is `init`, `on_load(state)` and `on_message(message, reply: []u8) -> int`, messages go through fixed buffers owned by the generated entry; `runtime.SaveState` keeps state in the browser storage. `ExtensionConfig.options` makes a web_build package (Karl2D, or a demo_kit demo) the options page, `content_script_file` sets the content script. `youtube_shorts/` is the full example (logic in `shorts.odin` for the background, the page and the tests; options page on raylib and Karl2D; `youtube_content.js`); its README says what was verified (mock pages, not live YouTube). Download button: yt-dlp / youtube-dl through a native messaging helper (`youtube_shorts/native` logic + `native_host` program, `native_host.odin` of the library registers it, a background reply `native:<text>` goes to the helper). `ExtensionInstall` writes a per user registry value on Windows. `ExtensionRelease` (release.odin, `--release`) installs for the main profile: Chromium family from a stable copy in `%LOCALAPPDATA%/<name>` that the user loads unpacked once, Firefox signed unlisted through `web-ext sign` (needs WEB_EXT_API_KEY/SECRET). Details, per browser install steps and verified browsers in its README. Needs `window` aliased in the service worker for odin.js.
