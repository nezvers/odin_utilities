# font: notes for agents

What is not obvious from the code of this library. The rules that hold for every library, the commands and the map of the libraries are in [../AGENTS.md](../AGENTS.md); the user facing description is in README.md.

- Vector fonts from outlines, two GPU methods: `font.odin` (`Font` over the bytes of a TrueType or OpenType file or collection, metrics in em units, `Method` = `.SLUG` or `.SCANLINE`), `sfnt.odin` + `truetype.odin` + `cff.odin` (the parser, pure Odin: a port of stb_truetype 1.28 that reads a glyph straight into the caller buffer through `OutlineSink`, no allocation, no C library, bounds checked reads; keep it bit for bit equal to stb_truetype, `parser_test.odin` compares every glyph), `outline.odin` (`FontGlyphCurves`: quadratic curves in a caller buffer, `CurvesMonotonic`), `raster.odin` (exact CPU coverage, the reference: `CurvesCoverage`, `CurvesRasterize`), `atlas.odin` (`Atlas` over a caller array of 4 float texels: header rows for the glyph table and a palette of colors, `AtlasGlyph` bakes on demand, `AtlasReserveText`, `AtlasClear`, `AtlasTakeDirty` gives the rows to upload), `slug.odin` + `scanline.odin` (the data of each method and `SlugCoverage` / `ScanlineCoverage`, the CPU models of the shaders), `special.odin` (the missing-character box and the solid glyph), `glyph.odin` (`GlyphInstance`, `EmitGlyph`, `EmitRect`), `atlas_file.odin` (bake ahead, `AtlasWrite`/`AtlasRead`), `rich.odin` (`RichParse`, `RichLayout(&rich, &atlas.faces, ...)`, `RichDraw`: BBCode-like tags and effects; bold and italic faces through `AtlasAddFace`, struck / slanted when a face is missing), `layout.odin` (`TextQuads`: six vertices per glyph with the slot and the palette index, `TextOptions` rotation / snap / wrap, `TextMeasure`), `shaders/` (GLSL 330 for raylib and the GL backend of Karl2D, HLSL for the D3D11 backend: keep each GLSL / HLSL pair the same), glue `glue_raylib/` and `glue_karl2d/` (`Renderer` over a caller vertex buffer, `DrawText`, `DrawRich`, `RendererFlush` with `deferred`, `RendererDraw` of a list, `TextMesh` = a VBO on raylib), `TextSystem` + `TextBox` (a user interface places text by a line box: ui `PainterUseVectorText`, kit `-define:DEMO_VECTOR_TEXT=slug|scanline`, pictures in `captures/<backend>_<method>`), demo `font` (demo_common has a `TextDrawer` hook that demo_raylib and demo_karl2d set), `tool/preview` and `tool/preview_karl2d` (`-- --shot out.png`).
- `font/ascii_cache.odin`: the ASCII tables (`ascii_glyph`, `ascii_advance`, `ascii_kern` rows made on first use; a `Font` is 34 KB bigger and its kerning rows are written when first used: warm it with `FontKerningWarm` before sharing it between threads); layout loops read characters with `fontNext` (ASCII with one comparison, else `simd_utils.Utf8Next`) and use `fontMetrics` / `fontPairKerning`, never `utf8.decode_rune_in_string`; `font/tool/measure_bench`.
- `odin test font -strict-style -vet` (34 tests, ~0.4 s) and `odin test font/demo_common`. `FONT_TEST_FILES=<a.otf;b.ttc>` compares more font files with stb_truetype (the repository has no CFF font: run it with one after a change to `cff.odin`). `vendor:stb/truetype` of Odin dev-2026-11 has a `fontinfo` that is 8 bytes shorter than the C struct (`vhea`, `vmtx` are missing): the tests pad it (`StbInfo`); nothing else in this repository uses stb_truetype. The shaders are not unit tested: the CPU models are (against the exact rasterizer), the screenshots of both frameworks check the shaders. The Karl2D D3D11 shaders must read every texture through a sampler of the same register (Karl2D checks it) and `point` is a reserved word in HLSL. The Slug shaders are translations of the MIT licensed reference (credit in README and the shader files); the Scanline Sweeper code is written from the paper, not from its MPL listings.
