# ui: notes for agents

What is not obvious from the code of this library. The rules that hold for every library, the commands and the map of the libraries are in [../AGENTS.md](../AGENTS.md); the user facing description is in README.md.

## Where things are
- `ui/docs/INVENTORY.md` lists the files and what each widget and style does (grep by name). `odin run tool/todo -- limits ui` prints what widgets do not do.
- Layout ported from Clay (MIT, credited in README); the look follows Baldr (zlib, credited in `default_style/default_style.odin` and README; no code of it).
- Packages: `default_style/` (`ui_default`: `Painter` + default style), `kit/` (Painter + input over demo_kit; loads fonts once per backend), `glue_raylib/`, `glue_karl2d/` (Painter + `InputPoll`, `Fonts`, `FontsLoad`, `PainterUseFonts/PainterUseVectorFonts`), `demo_common/` (all demos with scripts; `demo_imgui` follows Dear ImGui's demo window).

## Rules for widgets
- A widget states what it does not do: a `Limits:` line in its source header and the same words in "Known limits" of `ui/README.md`. A new widget gets them in the commit that adds it; lifting a limit changes both and ticks `ui/TODO.md`.
- Pointer is tested against the hit boxes of the last frame: a click needs a frame of layout first (scripts `Wait(3)` at start). Ids are hashes of the name in the container (`"Save##2"`); `UiIdPath("Window", "Widget")` finds one outside a frame.
- Numbers a widget draws from (plot values, chart series) must live until `UiRender`; the compiler warns about a literal or local array.
- Theme is saved/loaded/edited by reflection (`theme_io.odin`): a new Theme field needs no change besides the two constants; `ThemeFromAccent` must stay equal to `THEME_DARK`.
- Color picker: `ColorMode` (SQUARE, HSV, HSL, RGB, OKLCH) is `WidgetState.mode` (dropdown `##mode`); `COLOR_STRIP` actual 0 hue, 1 alpha, 2 channel bar, 3 horizontal alpha; strips are one pixel wide (`strips` in `default_style/color.odin`), never cells. Timeline CURVE/EXP handle: `CurveHandleAlong`.
- Edit mode: `edit.odin` (`UiEditMode`, `EDIT_COVER`, `Context.edit`); style editor `default_style/style_editor.odin`, `style_store*.odin`. `ui/styles` holds saved styles (`odin run ui/tool/styles` writes dark and light); `current.style` is git ignored and unused in tests/captures (`demoStyleEnabled`).

## Writing demo scripts
- Click at fixed coordinates computed from layout (window (40,40), padding 10, controls 28 high): widths must be `Fixed` so fonts do not move them. For layouts that depend on text widths find widgets with `ui.UiElementRect` and click with `kit.ClickAt(&target)`.
- A check must not depend on where text wraps: backend fonts differ. Run scripts in windows too (`demo_kit/tool/captures -- --karl2d ui`), not only headless.
- A Capture shares its frame with the step after it: put a Wait behind it. A picture with a caret pins the blink first (`state.app.ctx.time = 0` in a Check). A picture showing time or rate gets fixed numbers from a Check before its Capture.
- An id needed from inside a loop or nested scope is stored while declaring (`state.pick_id = ui.UiId(c, name)`): `UiIdPath` cannot name an element under an `IdFromIndex` parent.
- Compare a small region exactly with `kit.CaptureAt` (masking frames). Gamepad: `kit.PadTap`, `kit.PadButton`, `Input.pad_pressed`. Drag: `kit.MoveAt(&target)` + `MouseDownStep/MouseUpStep`, long delay before a Capture.
- Fonts in the kit: `kit.FontLoad(ctx, bytes, size, glyph_count, first_glyph)`; with `DEMO_VECTOR_TEXT` a kit font is a face of the text system (`font.ATLAS_FACES` 16: 0..3 family, 4..15 program, ui takes 8..15).

## Tests
- `odin test ui`, `odin test ui/demo_common`, `odin test ui/default_style` (theme generator; `style_test.odin` renders a frame with every widget into a counting painter, both themes, with and without icons: add a new widget to its frame).
- Long text and keys: `UiTextField` keeps the caret in view with `state.scroll.x` (computed from the caret and the width of the last frame, 0 without the focus) and passes it as `DrawInfo.scroll`; a style that draws `TEXT_FIELD` must move the text by it and clip to the box (`default_style` `DrawTextField` does, tests in `style_test.odin` and `ui_test.odin`). `read_only` is a parameter of `textFieldEdit(Keys)`: add every new editing operation behind it. The kit repeats held keys (`demo_kit` `InputRepeat`, `Input.keys_repeat`); a new glue must either feed repeats into `keys` itself (raylib, Karl2D do) or use `keys_repeat`.

## Soft edges
- `aa.odin` builds anti-aliased shapes as triangle lists with a coverage per vertex (fringe of NanoVG, see `docs/ANTI_ALIASING.md`); a painter draws them through `fill_mesh` and keeps its storage in `Painter.mesh` (`ui_default.SmoothReady`: without storage everything falls back to the plain shapes, test painters have none, so stored test pictures of those are unchanged). Glue sets `fill_mesh` + `mesh` (`glue_karl2d`, `glue_raylib`, `kit`); karl2d needs the fork's `draw_colored_triangles` (uncommitted in the fork: its rules forbid committing there without being told). New shapes go in `aa.odin` (pure, tested by their covered area in `aa_test.odin`) and `default_style/smooth.odin` (painter side).
- Demo `smooth` (`demo_smooth.odin`) shows the shapes with a toggle for the plain ones; the stored captures of all demos were regenerated when rounded corners, ports and cables became soft.
- Demo `nota` (`demo_nota.odin`): four screens of the DAW Nota (arrangement, mixer, modular, piano roll) from its screenshots; hand drawn parts are marked `GAP` and match `docs/NOTA_GAP.md` (what Nota has that the library lacks, by priority). A script stops its clock (`state.frozen`) so the pictures `nota_*` are the same every run. When a gap is closed, use the widget in the demo, remove its `GAP` mark and its row.
- `Layout.exact = true`: padding and gap are taken as they are, also zero (a zero padding and gap otherwise means "the style's"); panels, windows, `UiRow` and `UiColumn` honor it. Use `UiRow`/`UiColumn` for containers that draw nothing, `UiPanel` with `exact` for flush drawn sections.
- `UiValueBar` (`widgets_valuebar.odin`, kind `VALUE_BAR`, style `default_style/value_bar.odin`): behavior is the widget, look is the style; `ValueBarSpec` (range, snap, bipolar, `to_text` / `from_text`). The typed text lives in `Context.entry_buffer` (one bar at a time); the typing is a `UiTextField` inside an element with the bar's id, so `UiId(ctx, "##entry")` is its field. Tests at the bottom of `ui_test.odin` (they must advance more than a double click between presses).
- `UiPianoRoll` (`piano_roll.odin`, kind `PIANO_ROLL`, style `default_style/piano_roll.odin`): all positions are the arithmetic `PianoRollAreas/BeatX/PitchY/NoteRect`, shared by pointer and style. `view.top_pitch` is the top edge (row above it is top_pitch - 1). The `nota` demo uses it; tests at the bottom of `ui_test.odin` (`rollClick` waits more than a double click).
- `UiFreqGraph` (`freq_graph.odin`, `FREQ_GRAPH`) and `UiWaveform` (`waveform.odin`, `WAVEFORM`), styles in `default_style/freq_graph.odin` and `waveform.odin`: positions are pure arithmetic (`FreqGraphX/Y/Node`, `WaveformX/SampleAt`) shared by pointer and style; the curve is `FreqBandResponse` (RBJ). Demo `editors` has both (script drags a node and selects a region); nota's EQ card uses the graph. Tests at the bottom of `ui_test.odin` (`freqDrag`, `waveDrag` wait more than a double click).
- `UiMixerFader` (`mixer_fader.odin`, `MIXER_FADER`, style `default_style/mixer_fader.odin`): the levels travel to the style in `DrawInfo.values` (the program's `MixerLevels`, alive until UiRender). `timeline_grid.odin`: `TimelineView.tempo` > 0 makes `RulerDraw.beat_seconds` > 0 and the style draws bars and beats (`barsRuler`); the times stay seconds. Tests at the bottom of `ui_test.odin`.
- `widgets_device.odin`: `UiPresetSelector`, `UiDeviceCard` (deferred end closes the body row and the panel; the proc returns false while folded), `UiDeviceSection`, `UiTrackHeader` are compositions: ids of the parts are `"##on"`, `"##preset"` (`"##prev"`, `"##list"`, `"##next"` inside), `"##fold"`, `"##close"` under the card id, `"M##m"`, `"S##s"`, `"R##r"`, `"##volume"`, `"##pan"`, `"##input"` under the track id. Tests at the bottom of `ui_test.odin`; demo `chain`; the nota device strip uses the cards.
- `widgets_pads.odin` (+ `default_style/pads.odin`): six small widgets, each its own style kind (`RANGE_SLIDER`, `XY_PAD`, `WHEEL`, `SCROLL_BAR_THIN`, `KEYBOARD`, `STEP_GRID`; what a kind reads from `DrawInfo` is in the comment at its entry in `style.odin`). Pointer arithmetic is pure (`KeyboardKeyRect/At`, `StepGridCellAt`, `ScrollBarThumb`). The step grid paints the line of cells between two frames of a fast drag. Demo `pads`.
- `picker.odin`: `UiPicker` (parameter picker and command palette), `PickerFilter` scoring is pure and tested; rows reuse the `DROPDOWN_ITEM` kind, so no style proc of its own. Its field id is `IdFromString("##query", panel id)`. Demo: chain ("Modulate...").
- `overview.odin` (+ `default_style/overview.odin`, kind `OVERVIEW`): `Overview` is kept by the program (timeline, view, total, sections; the style reads it through `DrawInfo.user`). Only `view.origin` and `view.zoom` change; the window width is `view.rect.z` of the last drawn timeline. Used in the nota arrangement.
- `clip_body.odin` (+ `default_style/clip_body.odin`, called by `DrawClip`): `TimelineClip.body` (slices of the program, copied nowhere) reaches the style as `ClipDraw.body`; placement is pure (`ClipBodyNoteRect/Peak/StepRect`, `ClipBodyArea`) and tested. Used by the nota arrangement.
- `scale_picker.odin`: `UiScalePicker` composes two `UiDropdown` and twelve `UiChip` (ids `"##root"`, `"##scale"`, `"<note> ##n<degree>"`: a space before `##` so a sharp does not start the separator). Demo `pads` (the keyboard lights the scale). Keyboard black keys are outlined so lit ones do not blur into lit white keys.
- `mod_matrix.odin` (+ `default_style/mod_matrix.odin`, kind `MOD_MATRIX`): data is the program's `ModMatrix` (names and amounts, passed to the style in `DrawInfo.user`); cell geometry is pure (`ModMatrixAreas/CellAt/CellRect`). `matrix` is an Odin keyword: use another name for variables. Demo `modulation`.
