# ui: notes for agents

What is not obvious from the code of this library. The rules that hold for every library, the commands and the map of the libraries are in [../AGENTS.md](../AGENTS.md); the user facing description is in README.md.

- Where things are: `ui/docs/INVENTORY.md` lists the files of the library and what each widget and style does (grep it by name). `odin run tool/todo -- limits ui` prints what the widgets do not do.
- Layout ported from Clay (MIT, credited in README); the look follows Baldr (zlib, credited in `default_style/default_style.odin` and the README; no code of it).
- `demo_common/demo_examples.odin`: the examples are chosen from a dropdown (`UiDropdown` `##examples`, 19 options; a script opens it with `tabBox()` and clicks the option with `tab(n)`), the first one is Rebind (a game's controls page: `UiBindingField` per input, `ui_kit.GlyphOf`, pictures for the face buttons through a texture made in memory; the script drives it with `kit.PadTap`; the demo kit has gamepad input: `kit.PadButton`, `Input.pad_pressed`; the other tabs are numbered from 1 in `tab(n)`), Baldr's 01_hello, 04_controls, 03_scroll, 17_toasts, 02_theme_lab (the theme made from a picked accent) 05_overlays (a `UiMenu` inside of a button tag is drawn as that button and opens its popup under it) 21_charts, 09_jobs, 19_markdown and 32_chat (bubbles: panel tags "bubble" / "mine", `UiRichText(..., max_width)`, `UiScrollSet(c, id, 1e9)` for some frames follows the end) , 33_reading (a page in a theme area), 20_shortcuts, 07_code and 37_custom (a widget made in the demo: `UiInteract` + a CUSTOM draw proc with `ui_default.PainterOf(ctx)` + `UiNavBlock`), 34_mentions and 35_spring (`UiDragRest(ctx, kind, seconds)` in dragdrop.odin: a drag stood still over the widget; a script drags between found places with `kit.MoveAt(&target)` + `MouseDownStep` / `MouseUpStep`, and sets a long delay before a Capture because frame times differ) and 28_lines (`default_style/lines.odin`: `LineDashed`, `PathDashed` with a phase that goes on around corners, `PathLines`, `RectCorners`) and 25_terminal (Log, Screen, and Big log: 20 000 rows of three cells in a `UiTable` with a selection over all of them) remade, a tab each (a picture that shows a time or a rate gets fixed numbers from a Check before its Capture: frame times differ between machines) (a toast is a floating element with the tag "popup" and `UiInteract`). A check of a script must not depend on where a text wraps: the fonts of the backends have other widths (run the scripts in the windows too, `demo_kit/tool/captures -- --karl2d ui`, not only headless). A Capture shares its frame with the step after it: put a Wait behind it. A picture with a caret pins the blink first (`state.app.ctx.time = 0` in a Check). An id the script needs from inside a loop or a nested scope is stored while declaring (`state.pick_id = ui.UiId(c, name)`): `UiIdPath` cannot name an element under an `IdFromIndex` parent.
- `demo_common/demo_emoji.odin`: the `emoji` demo (31_emoji): the picker is a `UiMenu` popover with grid cells (`UiInteract` + `.SELECTABLE`), emoji drawn by a CUSTOM proc from shapes (`DrawInfo.actual` the emoji, `cursor` the skin tone), shortcodes in the text, `UiTextInsert` (textformat.odin) writes at the caret; pictures `emoji_*`.
- `demo_common/demo_shell.odin`: the `shell` demo, six tabs (control centre, launcher, dock, taskbar, desktop, clock applet) from Baldr's desktop shell examples; windows and workspaces are plain data; `UiNavBlock(.UP/.DOWN)` after a text field lets the arrows walk a list while it keeps the focus; the rectangles of the last frame are kept in the state for pointer logic (`UiElementRect` is only valid after the frame); pictures `shell_*`.
- Edit mode (`edit.odin`: `UiEditMode`, `EDIT_COVER`, `Context.edit`) and the style editor (`default_style/style_editor.odin`, `style_store.odin` + `style_store_file.odin`, `theme_io.odin`: Theme as text by reflection, so a new Theme field is saved, loaded and editable without a change; add it to the two constants and `ThemeFromAccent` keeps equal to `THEME_DARK`). Demos: `demo_style.odin` gives every demo the `Style` button, `ui/styles` holds the saved styles (`odin run ui/tool/styles` writes dark and light; `current.style` is git ignored and is not used in tests or captures: `demoStyleEnabled`), the `style editor` demo embeds it with a memory store. A script that wants a small region compared exactly uses `kit.CaptureAt` (masking frames).
- Demo names in the menu: `rebind controls` (first; `demo_rebind` in demo_examples.odin shares its state), `baldr gallery`, `baldr examples`, `baldr shell`, `baldr windows`, `baldr emoji`. Color picker: `ColorMode` (SQUARE, HSV, HSL, RGB, OKLCH; the mode is `WidgetState.mode`, a dropdown `##mode` in the picker), `COLOR_STRIP` has actual 0 hue, 1 alpha, 2 channel bar, 3 horizontal alpha; the strips are one pixel wide (`strips` in `default_style/color.odin`), never cells. A timeline CURVE / EXP handle is pulled along the segment (`CurveHandleAlong`).
- `demo_common/demo_windows.odin`: the `windows` demo (23_chrome, 38_windows, 14_bar_applets): windows with their own frame as floating elements (title bar by `UiInteract`, grips, raise by z order), two windows of one state, a bar of applet slots with Restart; pictures `windows_*`.
- `demo_common/demo_gallery.odin`: the first page of Baldr's gallery remade (dark, light, a page of all icons). Its script finds widgets by `ui.UiElementRect` and clicks with `kit.ClickAt(&target)`: use that for a layout that depends on text widths. Fonts in the kit: `kit.FontLoad(ctx, bytes, size, glyph_count, first_glyph)`, with `DEMO_VECTOR_TEXT` a kit font is a face of the kit's text system (`font.ATLAS_FACES` is 16: 0..3 the family, 4..15 for a program (the ui takes 8..15)).
- `default_style/` (package `ui_default`: `Painter` + default style), `kit/` (Painter + input over demo_kit, used by the demos: loads the fonts once per backend), `glue_raylib/`, `glue_karl2d/` (Painter + `InputPoll`, `Fonts` + `FontsLoad` + `PainterUseFonts` / `PainterUseVectorFonts`), `demo_common/` (widgets, layout, styles, navigation demos and `demo_imgui`, the layout of Dear ImGui's demo window, with scripts; ImGui is the demo it follows). Scripts click at fixed coordinates computed from the layout (window at (40,40), padding 10, controls 28 high): widths must be `Fixed` so fonts do not move them.
- Pointer is tested against the hit boxes of the last frame; a click needs a frame of layout first (scripts `Wait(3)` at the start). Ids are hashes of the name inside the container (`"Save##2"`), `UiIdPath("Window", "Widget")` finds one from outside a frame.
- A widget states what it does not do: a `Limits:` line in the header comment of its source file and the same words in the "Known limits" list of `ui/README.md`. A new widget gets them in the commit that adds it; lifting a limit changes both and ticks `ui/TODO.md`.
- `odin test ui`, `odin test ui/demo_common`, `odin test ui/default_style` (the theme generator, and `style_test.odin`: a frame with every widget rendered into a painter that only counts, in both themes, with and without icons; add a new widget to its frame). Numbers a widget draws from (plot values, chart series) have to live until `UiRender`: the compiler warns about a literal or a local array.
